Web - backup leak

문제 설명 : 평범해 보이는 회사 소개 홈페이지이다. 목표: 배포 흔적을 추적해 서버에 남은 백업 아카이브를 찾고, 그 안의 삭제된 데이터를 복원하라 write up: 페이지에서 누를 수 있는것들은…

문제 설명 :

평범해 보이는 회사 소개 홈페이지이다. 


목표:

배포 흔적을 추적해 서버에 남은 백업 아카이브를 찾고, 그 안의 삭제된 데이터를 복원하라

write up: 

페이지에서 누를 수 있는것들은 다 눌러봤다. 
공지사항에는 홈페이지 서버가 이전 완료 되었다는 정보를 찾을 수 있었고 옆의 Link란은 클릭할 수 있을것 처럼 생겼지만 누를 수 없다. 
서버 이전 후 외부 링크가 끊겨 담당자가 확인중이라 한다.

개발자도구를 열어 코드를 분석해보려 했다.
source에 js파일이 있는것을 알 수있었다. 
v2부터 백업 아카이브는 빌드마다 버전이 붙은 이름으로 기록된다는것, 
archiveDir 이 /backup/
archivePattern이 "backup_{sha}_{data}.tar.gz
라는것을 알 수 있었는데 tar.gz를 보면 압축폴더형식이라는것을 알 수 있다.

다시 홈페이지를 보았는데 copyright 밑에 build 정보가 눈에 띄었다.
알 수 없는 문자열과 배포년월일, deploy.sh v2 라는것을 알 수 있었다.

archivedir과 archivepattern 에 맞춰 url을 입력하니 압축폴더가 열렸다.

flag는 폴더안의 파일들에 잘라져 있었다.
붙여서 넣으니 해결 할 수 있었다.

꼭 network창에서 모든 문제의 해결 실마리가 있는것은 아니라는것을 알게되었다.
