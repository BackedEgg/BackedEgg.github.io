Web - Poisoned Reset Link

문제 설명: 비밀번호를 잊었을 때 재설정 링크를 발급해주는 라이딩 모임 포털이다. 목표 : 재설정 링크가 공격자의 주소를 가리키게 만들어라. write up: 페이지에는 이메일 입력해 재설정요청을 …


문제 설명:

비밀번호를 잊었을 때 재설정 링크를 발급해주는 라이딩 모임 포털이다.


목표 :

재설정 링크가 공격자의 주소를 가리키게 만들어라.

write up: 

페이지에는 이메일 입력해 재설정요청을 누를 수 있는 버튼, 재설정 토큰과 새 비밀번호를 입력해 비밀번호를 변경할 수 있는 버튼, 이메일과 비밀번호를 입력해 로그인할 수 있는 버튼이 있었다.
밑에는 admin@club.local 계정이 admin 계정이라는것을 명시하고 있었다.

우선 기본적인 member@club.local로 재설정이메일을 발송하면 "재설정 링크를 생성해 이메일로 발송했습니다. (데모: 실제로는 이메일이 발송되지 않았습니다.")가 뜨는데 토큰값은  뜨지 않고 resetlink도 발송되지 않는다.

토큰이 나와야 변조를 할 수가 있는데 토큰이 보이지 않으니 문제풀기가 너무 어려웠다.

토큰을 내가 html에서 찾아야하는것인지 아니면 어떤식으로 접근할 수 있는지 알아보기 위해 우선 토큰과 토큰의 발급방식을 먼저 찾아보았다.

토큰 : 네트워크 통신에서 특정 데이터에 접근할 권한이 있다는것을 증명하는 암호화된 입장권
토큰의 발급 방식 : 사용자가 로그인에 성공하면 서버가 그 사용자의 신원을 증명할 수 있는 고유한 '토큰'을 부여하고, 이후 요청부터는 이 토큰을 제시하여 인증을 받는 방식.

 

라는 답변을 얻을 수 있었다.

즉, 토큰은 서버가 클라이언트와 소통하면서 얻게 되는것으로 html에서 찾을 수 있는것은 아니었다.

다만, 다시 문제페이지를 봐도 재설정링크에 담긴 토큰을 확인하라는 
말뿐 재설정 링크를 찾을 수는 없었다...

힌트를 보아도 별 소득이 없었다.

여러 시도 중 챗 지피티 프로가 추천해준 host header injection 를 시도해보았더니 reset link와 토큰이 발급되었고 그 토큰으로 비밀번호를 수정하고 로그인하니 flag가 떴다.

burpsite로 host를 수정하는공격인데 이를 이해하기위해서는 많은 선행지식이 필요했다.



GET : 서버로부터 정보를 요청할 때 사용되는 http 메서드
조회및 가져오기 (읽기요청)

데이터가 담기는 곳 : http 패킷 header

post방식: 정보를 생성/업데이트하기 위해 서버에 데이터를 보내는 http 메서드, 서버가 요청에 포함된 데이터를 처리하도록 지시하는 메서드

데이터가 담기는 곳 : http 패킷 body

Get과 post의 차이점?

get은 일반적으로 body를 사용하지않음 
주로 url 에 데이터를 전달

post는 주로 body 에 데이터를 전달함.

POST /forgot-password HTTP/1.1

post : HTTP 메서드. 서버에 데이터를 전달해 처리하도록 요청
/forgot-password : 요청 대상 경로. 비밀번호 재설정 기능과 관련된 엔드포인트로 보임
HTTP/1.1 : 사용하는 HTTP 프로토콜 버전

Host: 127.0.0.1:8173
요청할 서버의 호스트와 포트를 나타냄
post를 받는쪽
(http/1.1 에서는 host헤더가 필수임)

도메인 : 서버를 찾아가기 위해 사용하는 이름
서버 : 요청을 받아처리하는 컴퓨터 또는 프로그램
이때 서버가 이 host값을 검증할 수도 있고 검증하지않을수도 있음

도메인 != 서버
그렇기에 도메인이 달라져도 서버가 host값을 검증하지않는다면 연결이 될 수 있음

참고로 이 host값은 application level에 있으므로 host가 바뀐다고 무조건적으로 통신이 안되는것은 아니다.


그 외 헤더들도 조금 보았다.

Content-Length: 25
요청본문에 포함된 데이터의 길이를 바이트 단위로 나타냄

sec-ch-ua-platform: "Windows"
브라우저의 client hints 헤더 중 하나, 자신의 플랫폼을 Windows라고 알려주는 정보

sec-ch-ua: "Not A(Brand";v="99", "Chromium";v="154"
브라우저의 브랜드 및 관련 버전 정보를 나타내는 Client Hints 헤더야
Chromium: Chromium 기반 브라우저와 관련된 정보
v="154": 해당 브랜드 버전 정보
"Not A(Brand";v="99": 호환성 등을 위해 포함될 수 있는 GREASE 브랜드 항목

Content-Type: application/x-www-form-urlencoded;charset=UTF-8
요청 본문이 어떤 형식으로 인코딩되어 있는지 서버에 알려줌

sec-ch-ua-mobile: ?0
브라우저가 보내는 모바일 환경 관련 Client Hints 정보임.
?0: 모바일 환경이 아님
?1: 모바일 환경임


Accept: */*
클라이언트가 응답으로 받을 수 있다고 표시한 미디어 타입을 뜻함.
application/json: JSON 데이터
text/html: HTML 페이지
text/plain: 일반 텍스트

Origin: http://127.0.0.1:8173
요청이 시작된 출처임
프로토콜 : http
호스트 : 127.0.0
포트 : 8173

Sec-Fetch-Site: same-origin
요청이 시작된 페이지와 요청 대상 사이의 출처 관계를 알려줌.
same-origin은 브라우저가 판단하기에 요청을 시작한 페이지와 요청 대상이 같은 출처라는 의미

same-site: 같은 사이트에 속하지만 출처는 다를 수 있음
cross-site: 서로 다른 사이트에서 발생한 요청
none: 주소창에 URL을 입력하는 등 사용자 주도의 탐색에 사용될 수 있음

Referer: http://127.0.0.1:8173/
요청이 발생한 페이지의 주소를 나타냄.
