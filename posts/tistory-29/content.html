SQL Injection 을 배우려고 했을때 가장 막혔던 부분은 SQL 구문이 어떻게 작성되는지, 어떤식으로 동작하는지였다. 그래서 처음부터 조금씩 배워보려고한다.

 

우선 SQL이 무엇인지부터 알 필요가 있다.

 

SQL(Structured Query Language, 구조화된 쿼리 언어)은 관계형 데이터베이스 관리시스템(RDBMS)의 데이터를 관리하고 처리하기 위해 설계된 특수 목적의 프로그래밍 언어이다.  

 

데이터베이스에 대해서 먼저 알아야할것 같다.

 

우선 데이터베이스는 데이터를 체계적으로 보관하고 관리하는 공간이다.

예를 들면서 이해해보자.

웹사이트가 회원 정보를 저장한다면, 그 안에 users라는 테이블(table)을 둘 수 있다.

id user name password
1 alice apple123
2 bob banana456
3 charlie cherry789

이때, 테이블은 엑셀의 표와 비슷하게 생각하면 된다.

  • 테이블: 회원 정보처럼 같은 종류의 데이터를 모아 놓은 표
  • 열(column): id, username, password처럼 각 데이터의 항목
  • 행(row): 회원 한 명에 관한 데이터 한 묶음
  • 값(value): 특정 행의 특정 열에 들어 있는 내용. 예를 들어 bob 행의 id 값은 2

위 표에서 bob을 찾는다는 것은 username 열의 값이 bob인 행을 찾는 것이다.

데이터베이스의 테이블(table)은 데이터를 정리해 둔 표라고 생각하면 된다. 예를 들어 users라는 테이블이 다음과 같다고 가정해 보자.

username password
alice apple123
bob orange456
admin 비공개

가로로 놓인 한 사람의 정보는 행(row)이고, username, password처럼 세로로 구분한 항목은 열(column)이다.

SQL은 이 표에 저장된 데이터를 조회하거나 변경할 때 사용하는 언어다. 그중 SELECT는 데이터를 조회하는 명령이다.

SELECT username
FROM users
WHERE username = 'bob';

순서대로 읽으면 다음과 같다.

  • SELECT username: username 열을 보여줘.
  • FROM users: users 테이블에서 찾아줘.
  • WHERE username = 'bob': username이 bob인 행만 골라줘.

이 쿼리를 실행하면 조건에 맞는 bob의 행을 찾는다. bob이 아닌 행은 결과에서 제외된다.

여기서 'bob'의 작은따옴표는 bob을 문자열 데이터로 취급하라는 뜻이다.

 

간단하게 명령어를 알아보자.

작업 명령어 의미
데이터 찾기 SELECT 조건에 맞는 행을 조회
데이터 추가 INSERT 새 행을 저장
데이터 수정 UPDATE 기존 행의 값을 변경
데이터 삭제 DELETE 기존 행을 제거

그럼 SQL Injection 을 배우고 있는 입장에서는 다음과 같은 질문을 할 수 있다.

로그인은 SQL로 어떻게 확인할까?

웹사이트의 로그인 기능은 사용자가 입력한 아이디와 비밀번호에 맞는 행이 있는지 조회할 수 있다.

SELECT username
FROM users
WHERE username = 'admin' AND password = '입력한 비밀번호';

AND는 양쪽 조건이 모두 참이어야 한다는 뜻이다.

따라서 username이 admin이라는 것만으로는 부족하다. password도 저장된 값과 같아야 해당 행이 반환된다. 정상적인 로그인이라면 이 두 조건을 모두 만족해야 한다.

그렇다면 SQL Injection은 어떻게 일어날까?

앞에서는 서버가 아이디와 비밀번호를 확인할 때 다음과 같은 SQL을 사용할 수 있다고 했다.

SELECT username
FROM users
WHERE username = 'admin' AND password = '입력한 비밀번호';

여기서 'admin'과 '입력한 비밀번호'는 SQL 명령이 아니라 비교할 데이터다. 서버는 username과 password가 모두 일치하는 행을 찾는다.

문제는 웹사이트가 사용자의 입력값을 SQL 문장에 그대로 이어 붙여 만들 때 생긴다. 다음은 취약한 방식의 예시다.

query = (
    "SELECT username FROM users WHERE username = '"
    + username
    + "' AND password = '"
    + password
    + "'"
)

사용자가 아이디에 admin, 비밀번호에 hello를 입력하면 서버가 만든 SQL은 다음과 같다.

SELECT username
FROM users
WHERE username = 'admin' AND password = 'hello';

여기까지는 처음 예상한 형태와 같다. 그런데 아이디 입력란에 admin' -- 를 넣으면 어떻게 될까? 비밀번호에는 틀린 값을 넣었다고 가정하자.

아이디: admin' -- 
비밀번호: wrong

서버가 입력값을 그대로 이어 붙이면 다음 SQL이 만들어진다.

SELECT username
FROM users
WHERE username = 'admin' -- ' AND password = 'wrong';

이 문장을 앞에서부터 살펴보자.

  1. admin 뒤의 '가 문자열을 닫는다.
  2. -- 뒤의 내용은 주석으로 처리된다.
  3. 따라서 원래 있어야 할 AND password = 'wrong' 조건이 검사에 사용되지 않는다.

결국 데이터베이스가 검사하는 핵심 조건은 다음과 같아진다.

WHERE username = 'admin'

admin이라는 행이 있다면 비밀번호가 틀려도 그 행이 조회될 수 있다. 사용자가 입력한 글자가 단순한 데이터로 취급되지 않고 SQL 문장의 의미를 바꾼 것이다. 이것이 SQL Injection의 기본 원리다.

다만 행이 조회된다고 해서 모든 웹사이트에서 곧바로 로그인이 성공하는 것은 아니다. 서버가 조회 결과를 어떻게 처리하는지에 따라 실제 영향은 달라진다. 방금 예시는 조회된 행을 로그인 성공으로 처리하는 취약한 프로그램을 가정한 것이다.

--는 왜 쓰는 걸까?

원래 SQL에는 아이디 조건 뒤에 비밀번호 조건이 이어진다.

WHERE username = 'admin' AND password = 'wrong'

입력값으로 문자열만 닫으면 뒤에 붙는 SQL 때문에 문법 오류가 날 수 있다. --는 그 뒤의 내용을 주석으로 만들어, 비밀번호 조건이 실행되지 않도록 하는 역할을 한다.

주석 문법의 세부 조건은 데이터베이스 종류에 따라 다를 수 있다. 따라서 이 입력이 모든 웹사이트에서 똑같이 동작하는 것은 아니다.

어떻게 막을 수 있을까?

핵심은 SQL 문장의 구조와 사용자 입력값을 분리하는 것이다. 이를 위해 매개변수화된 쿼리(parameterized query)를 사용한다.

query = (
    "SELECT username FROM users "
    "WHERE username = ? AND password = ?"
)
cursor.execute(query, (username, password))

이 방식에서는 사용자가 admin' -- 를 입력하더라도, 데이터베이스는 이를 SQL 명령의 일부가 아닌 아이디 값 전체로 취급한다. 즉, 실제로 이름이 admin' -- 인 행을 찾을 뿐, 비밀번호 조건을 주석으로 바꾸지 못한다.

여기서 한 가지 더 주의할 점이 있다. 실제 서비스에서는 비밀번호를 예시처럼 평문으로 저장하고 비교하면 안 된다. 비밀번호는 적절한 비밀번호 해시 방식으로 저장하고 검증해야 한다. SQL Injection 방지와 비밀번호의 안전한 저장은 서로 다른 문제이므로 둘 다 필요하다.

정리하면, SQL Injection은 입력값이 SQL 문장의 구조를 바꾸도록 프로그램이 허용했을 때 발생한다. 앞에서 배운 작은따옴표는 문자열의 경계를, AND는 조건의 결합을, --는 뒤따르는 문장의 주석 처리를 이해하는 열쇠가 된다.
