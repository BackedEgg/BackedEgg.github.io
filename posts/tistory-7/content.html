Request Anatomy

문제요약:평범해 보이는 사내 공지페이지이다. 딱히 별 다른 기능은 없다.

Write up:
맨 처음 페이지에 들어가고 내가 할 수 있는 행동들을 생각했다. 우선 사용자 화면에서 할만한 상호작용이 딱히 없었다.
그래서 관리자페이지를 활용하거나 wireshark를 이용해봐야겠다고 생각했다.

우선 어떤식으로 통신을 하는지 지켜보기 위해 wireshark로 패킷을 잡아보았다. 
정상적인 handshake이후에 서버에게 get을 보내고 서버가 
서버가 ok를 보내왔는데 이때, x-ctf-flag를 볼 수 있었다.

꼭 wireshark가 아니더라도 관리자모드에서 확인할 수 있었는데 
network 페이지의 response headers에서 찾아볼 수 있었다.

웹해킹을 처음배우는거라 무슨질문을 해야할지조차 몰라서 막막했는데 막상 찾고 보니 쉬웠다.

wireshark를 사용하면서 패킷을 분석하는 능력도 조금 기른것 같다. 누가 보낸건지, 누구에게 보내는 건지 보면서
핸드쉐이크 하는 과정을 직접 보고 사이트내의 통신도 지켜보니 조금 신기했다.
관리자모드도 처음 보았는데 다양한 기능들이 있어서 앞으로 활용할 수 있을것 같았다.

Method Gate

문제요약 : 관리반 인프라의 가동상태를 보여주는 보드가 있고 서비스 이름으로 개별조회를 할 수 있다.

Write up:
맨처음 페이지를 탐색했다. 센서를 개별조회 해볼 수 있다는것,  그렇지만 web,db는 식별자를 물려받기만 해서 온실센서를 가리키기만 한다는것, 응답형식이  json 이라는것, 점검 관련 항목은 화면조회에서 내려주지않도록 했다는것을 알 수 있었다. 그렇지만 개별조회로 web,과 db, cache, mail을 검색해봤다. 
{"service": "이름", "status":"ok"}의 형태로 페이지가 나왔다. }
wireshark로도 패킷을 잡아봤지만 딱히 얻을 수 있는 정보는 없었다.

관리자페이지를 열었다.
개별조회는 get형식인것을 알 수 있다.
cmd를 열어 

curl -X OPTIONS -i http://127.0.0.1:8109/status?service=web

를 쳐보았다. allow 에 이 페이지가 허용하는 메소드를 알아보았는데 post, get, options, head가 있었다. 
하지만 꼭 cmd가 아니어도 된다. console을 이용하는 방법은 다음과 같았다.  

fetch(window.location.href, { method: 'OPTIONS' })
  .then(response => {
    console.log(response.headers.get('Allow')) ;
    
  })
post의 형식으로도 보내면 어떻게 될지 궁금했다.
constole에 fetch 를 사용했다.



**fetch: 자바스크립트에서 서버와 http통신을 할 수 있도록 브라우저가 기본적으로 제공하는 내장함수이다.

서버에서 데이터를 가져올때( GET) 

fetch('url') # 서버에 (request)를 보내는 명령어, 기본적으로 GET요청이 날라감.
.then(response =>{ #fetch 요청이 성공적으로 끝난 다음에 실행할 할 일 지정.
 return response.json(); #서버에서의 응답(response)를 자바스크립트에서 다룰 수 있는  JSON 형태로 변환.
})
.then(data=> {
console.log(data); #콘솔창에 출력.
})


서버에 데이터를 보낼 때(POST) 

fetch('https://example.com', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({ #http 통신은 문자열만 전송할 수 있음, 해당 명령어는 json문자열로 변환하여 전달하는것을 의미
    name: '홍길동',
    age: 25
  })
})
.then(response => response.json())
.then(data => console.log('성공:', data))
.catch(error => console.error('에러:', error));



실제 사용한 코드 

fetch('http://127.0.0.1:8109/status?service=web', {
  method: 'POST'
  
})
.then(res => res.text())
.then(data => console.log(data));



JSON Only

문제요약 :
이용자 모임 서비스의견을 접수하는 창구 페이지이다. 화면에 나와있는 폼으로 보내면 오류가 난다.

페이지에는 알려진 문제 라는 글이 있었는데 이 폼으로 보내면 항상 content-type must be applicationi/json 오류가 난다고 한다. 접수 api를 json 전용으로 바꾸면서 화면 폼을 같이 고치지 못했다고도 한다.

그 밑의 접수 api규격에는 
엔드포인트 post/feedback, 본문형식 json, 필수 필드 message, 응답 : 접수된 내용을 그대로 되돌려줍니다
가 적혀있었다.

Write up : 
개발자도구를 열어보니 페이지의 말대로 feedback 페이지는 post를 보내고 있었고 다만 400 bad request 를 보내고 있었다.
정상적인 post를 보낼 수 있도록하는 명령어를 console에 넣어봐야할것 같다. 

실제 넣은 명령어 : 

fetch('http://127.0.0.1:8111/feedback', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    message: '홍길동',
    
  })
})
.then(res => res.text())
.then(data => console.log(data));




Locker Share

문제요약 :
개인물품 보관함을 관리하는 서비스페이지다. 로그인을 하면 내 락커에 메모를 남길 수 있고, '내 메모 내보내기'링크로 그 메모를 파일로 내려받을 수 있다.
내 계정으로 로그인한 채 다른 사람의 락커 메모를 열람하면 된다.

페이지에 들어가서 락커실 배치도를 보면 내가 쓰고 있는칸은 2번이고, 1번이 admin인것을 볼 수 있었다.
또한 락커배정(로그인)을 하는데 따로 비밀번호 인증 등의 권한 인증 절차가 따로 없었다. 
여기서 나는 url을 봤는데 api/notes/2/export라고 되어있었다.
숫자를 2에서 1로 바꾸니 풀렸다.

다만 이렇게 푸는건 아닌것 같아서 조금 더 생각해보았다.

우선 페이지에서 사용중인 json 형식이 body, id, owner, title 이었기때문에
이것들을 가지고 post fetch 를  작성해야겠다고 생각했다.
post가 되지 않았다. 그래서 사용가능한 옵션에는 뭐가 있는지 보았더니 

fetch(window.location.href, { method: 'OPTIONS' })
  .then(response => {
    console.log(response.headers.get('Allow')) ;
    
  })



GET, Header가 끝이었다.
그래서 GET으로 fetch 를 보내야겠다고 생각했다. 다만, 내보내기 주소는  /api/notes/번호/export 형식을 따랐다. 

fetch('http://127.0.0.1:8104/api/notes/1/export')
.then(response => response.text())
.then(data => console.log(data)


를 보냈더니 답이 나왔다.

막상 코드를 쓰고 나니 첫번째 방법이랑 살짝은 다르지만 결국 똑같은 경로 인거 같다.
